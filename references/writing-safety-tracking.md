# 写作安全追踪系统

> 全程写作合规追踪 + 实时合规建议 + 写作安全日志
> 覆盖全球各小说平台，每步处理记录追踪
> 去重说明：红线检测定义以 `references/content-safety.md` 为准，本文件专注追踪日志格式与安全等级评定。

---

## 一、系统架构

```
用户输入文本
    │
    ▼
┌─────────────────────────────────────────────────┐
│             写作安全追踪系统                      │
│                                                   │
│  Step 1: 前置安全检查记录                         │
│  Step 2: 处理过程追踪（去AI味/润色/蒸馏/仿写）  │
│  Step 3: 平台合规适配检查                         │
│  Step 4: 后置质量检测记录                         │
│  Step 5: 合规建议输出                             │
│  Step 6: 写作安全日志归档                         │
└─────────────────────────────────────────────────┘
    │
    ▼
  交付结果 + 合规报告 + 追踪日志
```

## 三、实时合规建议规则

### 3.1 检测到AI痕迹时

| 检测项 | 建议 |
|--------|------|
| 逻辑词密度>2/300字 | 建议降低逻辑词密度，用直接叙事替代 |
| 句长方差<0.5 | 建议打乱句式，长短句交错 |
| 情感标签词≥3处 | 建议用身体反应替代情感标签词 |
| 比喻密度>5次 | 建议减少比喻，用直接描述 |
| 前100字无具体细节 | 建议从具体场景切入，避免概括性开头 |

### 3.2 检测到平台违规风险时

| 平台 | 风险 | 建议 |
|------|------|------|
| 起点中文网 | AI率<10% | 建议全流程去AI处理后再次检测 |
| 番茄小说 | 200+维度AI检测 | 建议额外进行句式分布检查和调整 |
| 晋江文学城 | 叙事段AI检测 | 建议重点处理叙事段，对话段可适度放松 |
| Amazon KDP | AI disclosure | 建议在版权页标注AI辅助编辑声明 |
| 小説家になろう | R18禁止 | 建议删除过激描写或移至别站 |
| 문피아 | 선정적 묘사 | 建议添加19禁标签或删除过激内容 |

### 3.3 通用合规建议

| 场景 | 建议 |
|------|------|
| 输入内容过短(<50字) | 建议提供更多文本以获得更好效果 |
| 输入内容过长(>50000字) | 建议分段处理，每段3000-5000字 |
| 语言检测失败 | 建议手动指定语言 |
| 风格蒸馏文本不足 | 建议提供至少3篇参考文本 |
| 反AI评分<70分 | 建议进行二次去AI处理 |
| 作家不在风格库中 | 建议提供该作家的代表作品以提取风格 |

## 四、写作安全等级评定

| 等级 | 标准 | 说明 |
|------|------|------|
| ⭐⭐⭐ 非常安全 | 全部检查通过 + 反AI评分≥90 | 可直接发布 |
| ⭐⭐ 安全 | 全部检查通过 + 反AI评分≥80 | 建议微调后发布 |
| ⭐ 基本安全 | 全部检查通过 + 反AI评分≥70 | 建议二次处理后发布 |
| ⚠️ 需注意 | 检查通过但存在潜在风险 | 建议修改后重新检查 |
| ⛔ 违规 | 安全检测未通过 | 需修改后重新提交 |
